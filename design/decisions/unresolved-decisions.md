# Bounded Owner Decisions — Handwritten Practice

No option is selected. Recommended labels are proposals only.

## D-HP-01 — Problem-screen layout

- **A. Two-column session rail + work area (recommended):** stable context and low clutter; uses more horizontal space.
- **B. Single centered work card:** strongest focus and best narrow-screen behavior; session details become a compact header.
- **C. Collapsible left rail:** adaptable; adds a control and variable layout.

## D-HP-02 — Navigation during an active problem

- **A. Minimal top bar with Exit/Save (recommended):** protects focus; fewer destinations.
- **B. Persistent full sidebar:** fast navigation; encourages accidental session exits and visual clutter.
- **C. No navigation until completion:** strictest focus; frustrating if the learner must leave.

## D-HP-03 — Recognition requirement

- **A. Required on selected training layers (recommended):** explicitly trains transfer without burdening every direct problem.
- **B. Required on every Handwritten Practice problem:** strongest measurement; repetitive.
- **C. Optional drawer:** flexible; evidence becomes inconsistent.

## D-HP-04 — Paper timer

- **A. Visible but voluntary (recommended):** supports readiness without forcing submission; may create pressure.
- **B. Hidden until requested:** calmer; less time evidence.
- **C. No timer in practice:** simplest; time readiness must be collected elsewhere.

## D-HP-05 — Progress representation

- **A. Position plus dots (recommended):** concrete and compact; dots scale poorly for long sessions.
- **B. Thin progress bar plus `3 of 10`:** scales well; less informative about reviewed/flagged items.
- **C. Text only:** least distracting; weak visual orientation.

## D-HP-06 — Incorrect feedback placement

- **A. Replace the answer form (recommended):** one active task; learner must choose remediation/retry.
- **B. Inline directly below the answer:** preserves submitted context; can become a long page.
- **C. Right-side feedback panel:** supports comparison; divides attention and needs width.

## D-HP-07 — Remediation escalation

- **A. Recognition clue → first-line cue → prerequisite → partial example (recommended):** bounded and diagnostic; more state transitions.
- **B. One clue then full explanation:** faster; reveals too much quickly.
- **C. Learner selects help level:** gives control; can encourage premature solution viewing.

## D-HP-08 — Correct feedback depth

- **A. Confirm result/checks, then continue (recommended):** maintains solving ownership; little reflective explanation.
- **B. Show reasoning checkpoint comparison:** better reflection; risks turning into passive review.
- **C. Always show full solution:** easiest comparison; conflicts with controlled revelation.

## D-HP-09 — Session setup density

- **A. Goal presets with expandable advanced controls (recommended):** quick start plus control; some settings hidden.
- **B. Show all controls:** transparent; visually dense.
- **C. One-click recommended session:** lowest friction; gives the system more product authority.

## D-HP-10 — Framework

- **A. Keep Streamlit after design approval (recommended for the next prototype):** reuses backend and deploy path; requires disciplined state rendering.
- **B. Static HTML prototype, then decide production framework:** strongest visual control before commitment; duplicates prototype work.
- **C. Migrate production now:** maximum control; broad, premature decision and higher risk.
